# 提前开下一轮门禁设计

## 目标

玩家只能在当前轮敌人已经全部出现之后，提前开启下一轮。地图上仍然存活的敌人不会阻止提前开下一轮。这样可以保留提前开下一轮的金币奖励意义，同时避免玩家在当前轮还没刷完时连续堆叠多轮敌人。

## 当前行为

`startWave()` 可以在战斗中执行。它会把下一轮敌人追加到 `spawnQueue`，并根据估算的剩余压力发放提前开启奖励。因为按钮在战斗中保持可用，玩家可以在当前轮仍在刷怪时再次点击。

## 目标行为

- 第一轮或空闲状态：显示 `开始第 N 轮`，允许点击。
- 战斗中且 `spawnQueue.length > 0`：波次按钮禁用。
- 战斗中且 `spawnQueue.length === 0`，但地图上仍有敌人：显示 `提前开始第 N 轮`，允许点击。
- 提前开启仍然会追加下一轮敌人，并保留现有的提前奖励计算。
- 战斗中仍然禁止随机地图。

## 实现方案

新增一个小的判断函数，例如 `canStartNextWave()`。它只在游戏结束，或战斗中仍有敌人等待刷出时返回 `false`。

更新 `startWave()`：当 `canStartNextWave()` 返回 `false` 时直接退出。

更新 `drawControls()` 中的波次按钮：

- 当 `state.running && spawnQueue.length === 0 && enemies.length > 0` 时，使用 `提前开始第 N 轮`；
- 当 `!canStartNextWave()` 时禁用按钮；
- 保持现有颜色和布局。

## 边界情况

- 如果 `spawnQueue` 为空但地图上仍有敌人，提前开启有效。
- 如果 `spawnQueue` 不为空，即使只剩 1 个敌人等待刷出，也不能提前开启。
- 如果游戏已经结束，所有开轮操作都被阻止。
- 如果战斗已经结束并已发放清场奖励，下一次开轮属于普通开轮，不属于提前开轮。

## 验证

运行 `node --check game.js`。

微信开发者工具手动检查：

- 开始第 1 轮；敌人仍在刷出时，波次按钮禁用。
- 第 1 轮敌人全部出现、但尚未全部被消灭时，按钮显示 `提前开始第 2 轮` 并可点击。
- 点击后追加第 2 轮，并发放提前开启金币奖励。
- 战斗中随机地图按钮仍然禁用。
